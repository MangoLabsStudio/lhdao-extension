# 插件 dev 无损整合设计

日期：2026-08-03
状态：待确认

## 目标

让本地插件开发基线与远端 `dev` 一致，同时保留当前本地工作区包含的全部有效
功能。第一阶段只做基线整合、缺陷修正和发布验证，不重构大型模块。

## 当前状态

- 当前工作区停在旧的 `feat/engagement-capture`，并叠加约 2500 行未提交改动。
- `origin/dev` 已包含设备签名、请求幂等、产品体验控制器、发布校验和绝大多数
  本地 UI 改动。
- 本地部分新增文件是上述能力的旧版或重复实现。直接覆盖 `dev` 会删除安全和
  产品体验模块。
- `src/lib/guide-state.ts` 含一个真实 NUL 字节，Git 因此将 TypeScript 源码识别
  为二进制文件。

## 方案比较

### 方案 A：用当前工作区覆盖 dev

操作最直接，但会退回旧的 GraphQL、签名、产品体验和构建配置，功能风险最高。

### 方案 B：把旧分支直接 rebase 到 dev

可以保留提交关系，但旧分支与 `dev` 在相同功能上采用了不同文件边界，会产生
大量假冲突，最终仍需人工判断每个重复实现。

### 方案 C：以 dev 为功能超集，逐项核对本地差异

保留 `origin/dev` 的模块化实现，只移植本地独有且仍有效的变化。原工作区保持
不动，用作回查快照。此方案改动最小，也最容易证明功能没有丢失。

采用方案 C。

## 整合范围

1. 以当前 `origin/dev` 建立隔离工作区。
2. 对照旧工作区检查组件、入口、消息协议、GraphQL、存储、安全和产品体验能力。
3. 不移植已被 `dev` 等价或更完整实现覆盖的旧代码。
4. 保留本地 `0.2.2` 版本意图，但沿用 `dev` 的描述、Firefox MV3、发布脚本和依赖。
5. 把 `guide-state.ts` 中的真实 NUL 字节改为源码转义，保持运行时去重键语义。
6. 第一阶段不拆分 `background.ts`、`content.ts` 或大型控制器；这些重构另立任务。

## 功能保护

整合后必须继续支持：

- 任务同步、领取、动作捕获和验证；
- 一键配对、设备签名、请求限流退避和资金操作幂等；
- Lighthouse 成员标记、敏感内容过滤、侧边栏、Popup 和 Options；
- Product Experience L1/L2 授权、规则观察和证明提交；
- Chrome、Edge 和 Firefox MV3 构建及发布清单校验。

## 验证与发布

依次运行测试、类型检查、lint、三种浏览器构建和产品清单校验。随后检查提交差异，
将单一整合提交直接推送到远端 `dev`。推送后比较本地提交与 `origin/dev`，确保两者
指向同一个提交。

任何验证失败都会停止推送。远端在工作期间前进时，先拉取并重新验证，不强推。
